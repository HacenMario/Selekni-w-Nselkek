# سلكني ونسلكك — Selekni w Nselkek

منصة جزائرية تربط أصحاب الأعمال الصغيرة بمن ينجزها عنهم: صاحب العرض ينشر عملًا (مثل حمل أثاث من الطابق الثاني إلى الشاحنة)، وأول باحث عن عمل يقبل العرض يصبح مكلفًا به ويرى العنوان، والدفع يحدث مباشرة بين الطرفين عند الإنجاز.

**Platforme algérienne de petits services — Selekni w Nselkek** — Algerian gig marketplace PWA.

---

## بنية المشروع (Architecture)

```
├── src/                        # واجهة Next.js 16 (تنشر على Vercel)
│   ├── app/page.tsx            # نقطة الدخول (SPA)
│   ├── components/app/         # شاشات التطبيق + LiveOfferModal + CompleteProfileModal + ImageGallery
│   └── lib/                    # i18n (ar/fr/en) + API client + ضغط الصور + صوت التنبيه + PWA push
├── mini-services/api-server/   # خادم Express + Mongoose (ينشر على Railway)
│   └── src/
│       ├── models/             # User, Offer, Complaint, Subscription, Settings, Notification, PushSubscription
│       ├── routes/             # auth (Google + Magic Link), offers, media (GridFS), complaints, notifications, subscriptions, admin, images, stats
│       └── services/           # web-push, notifications, settings, superadmin
└── public/                     # manifest + sw.js + أيقونات PWA + العلم الرسمي + صوت التنبيه
```

- **قاعدة البيانات**: MongoDB فقط (Mongoose + GridFS للفيديو). لا توجد أي بيانات تجريبية — القاعدة تبدأ فارغة مع إعدادات النظام وحساب السوبر أدمن فقط.
- **السوبر أدمن**: يُنشأ تلقائيًا عند إقلاع الخادم من متغيرات `.env`.
- **قبول العرض ذري (Atomic)**: `findOneAndUpdate({status:'open'})` — أول من يقبل يفوز، والآخرون يحصلون على `409 ALREADY_TAKEN`.
- **الخصوصية**: عنوان العرض لا يظهر أبدًا في التغذية أو التفاصيل — فقط لصاحب العرض ولمن قَبِل.
- **الاشتراك**: لأصحاب العروض فقط (البحث عن عمل مجاني). صاحب العرض يدفع عبر BaridiMob/CCP ويُدخل المرجع → السوبر أدمن يؤكد → الاشتراك نشط لمدة قابلة للضبط.

## الميزات (v2)

- **ثلاث لغات**: العربية (RTL) / Français / English — زر أنيق يفتح قائمة منسدلة تعرض اللغات الثلاث مع **الأعلام الرسمية** (علم الجزائر الرسمي المرفق + علمي فرنسا وبريطانيا) و**مفتاح On/Off** لكل لغة. القائمة متاحة في كل الصفحات بما فيها تسجيل الدخول.
- **الوضع الليلي/النهاري**: لون ذهبي دافئ مريح في الليل بدل البرتقالي الحارق — كل النصوص واضحة في الوضعين، والزر متاح في شاشة الدخول أيضًا.
- **تسجيل الدخول بـ Google OAuth** و **Magic Link عبر البريد الإلكتروني** (nodemailer/SMTP). بعد الدخول الاجتماعي تظهر **نافذة إجبارية لا يمكن تجاوزها** لإكمال بيانات الحساب (الاسم، الهاتف، الولاية، الجنس، العمر، الصورة الشخصية، نوع الحساب)، ولا تظهر مرة أخرى بعد الإكمال (`profileComplete`).
- **ملف المستخدم الكامل**: الصورة الشخصية (Base64 مضغوطة)، الجنس، العمر، الولاية، الهاتف — تظهر للطرف الآخر: صاحب العرض يرى بطاقة العامل المكلف (صورة/جنس/عمر/ولاية/هاتف بزر اتصال)، والباحث يرى بطاقة صاحب العرض في تفاصيل العرض.
- **النافذة المنبثقة الحية للعروض**: بمجرد نشر العرض تظهر لكل الباحثين عن عمل في نفس اللحظة مع **صوت تنبيه** وزر "قبول العرض" وزر "تخطي الآن". عند قبول أحد المستخدمين يختفي العرض لدى الآخرين فورًا مع رسالة "تم قبول هذا العرض من طرف مستخدم آخر...". العروض غير المقبولة تظهر مجددًا عند تسجيل الدخول لمن لم يتخطّها.
- **الصور والفيديو**: حتى **10 صور** للعرض (Base64 مع ضغط تلقائي في المتصفح ≤500KB للصورة) + **فيديو بأي حجم** يُرفع عبر GridFS ويُبَثّ بدعم Range (تمرير سلس في المشغّل).
- **معرض الصور**: تمرير باللمس على الهاتف، أسهم يسار/يمين على سطح المكتب، والنقر يفتح الصورة **ملء الشاشة بدون أي تشويه** مع أسهم ولوحة مفاتيح.
- **فلاتر جديدة**: البحث النصي (عناوين ووصف)، الولاية، نطاق المبلغ (أدنى/أقصى)، الترتيب (الأحدث / الأجر تصاعديًا / تنازليًا) — مع شارة عدد الفلاتر المفعلة.
- **الشكاوى**: صاحب العرض والعامل المكلف يمكنهما تقديم شكوى عن العرض؛ تصل للسوبر أدمن فورًا (إشعار + مؤشر في اللوحة)، يعالجها ويرسل قرارًا يبلغ صاحب الشكوى.
- **أزرار في كل مكان**: زر الرجوع/الإغلاق بتصميم موحد، **زر Back to Top أنيق** في كل الصفحات (يظهر عند التمرير، يختفي تلقائيًا بعد ثوانٍ، يعود عند التمرير للأعلى)، والنقر على الشعار يعيدك إلى "حسابي"، وإعادة تحميل الصفحة تُبقيك في نفس المكان.
- **Skeleton loading أنيق** بشعار التطبيق واسمه أثناء التحميل.
- **لا اقتطاع للنصوص**: كل العناوين والأوصاف تظهر كاملة (`break-words`) مع احترام التجاوب وبدون تجاوز إطار الشاشة.
- **58 ولاية جزائرية** (التقسيم الإداري الرسمي الكامل 2019) بأسماء عربية وفرنسية في قائمة اختيار موثوقة تعمل على كل الأجهزة.
- PWA كاملة: تثبيت على الهاتف، إشعارات Web Push في الخلفية (Service Worker + VAPID)، شاشة إشعارات بأزرار أيقونية فقط.
- إحصائيات منفصلة لكل نوع حساب + لوحة سوبر أدمن (مستخدمون، عروض، اشتراكات، شكاوى، إعدادات، إشعار عام).
- تجاوب 100% من 360px حتى سطح المكتب دون أي تجاوز لإطار الشاشة.

## الميزات (v4)

- **إصلاح جوهري للوسائط**: الصورة الشخصية وصورة إثبات الدفع والفيديو أصبحت تظهر/تعمل بعد الرفع فورًا — التوكن يُمرَّر الآن بشكل صحيح عبر رابط الاستعلام لوسوم `<img>`/`<video>` التي لا ترسل ترويسة Authorization.
- **إدارة اشتراكات كاملة في لوحة السوبر أدمن**: كل اشتراك يعرض نوع الباقة، السعر، المدة، الحد الأقصى للمهام النشطة، المرجع، تواريخ البدء والانتهاء، الأيام المتبقية، وصورة إثبات الدفع (بعرض مكبَّر). فلترة حسب الحالة + ترقيم صفحات، وأزرار: موافقة / رفض / تعطيل فوري / **تمديد** (+7/+30/+90 أو أيام مخصصة).
- **تعطيل/تفعيل اشتراك أي حساب**: من تفاصيل المستخدم — قفل الاشتراك يمنع طلب اشتراكات جديدة ونشر العروض، مع إشعار تلقائي للعميل، وزر **منح اشتراك مجاني** فوري (بأيام محددة وباقة اختيارية).
- **صورة ترويجية لكل باقة اشتراك**: يرفعها السوبر أدمن من محرر الباقات (GridFS، حتى 1.5MB)، وتظهر للعميل في صفحة الاشتراكات.
- **إحصائيات ذكية ورسوم بيانية** في لوحة السوبر أدمن (بدون أي مكتبات خارجية — SVG خالص): حسابات جديدة يوميًا، مهام جديدة يوميًا، المداخيل اليومية، الاشتراكات حسب الحالة (دونات)، حسب الباقة، المهام حسب المجال والولاية، + مؤشرات ذكية: إجمالي المداخيل، متوسط قيمة المهمة، نسبة الإنجاز، نسبة الإلغاء.
- **صلاحيات كاملة للسوبر أدمن**: معفى من الاشتراك نهائيًا (نشر بلا حدود)، وحد المهام النشطة صار من **باقة المستخدم نفسها** بدل الإعداد العام.
- **تبويبات الإدارة تعمل بالنقر على سطح المكتب والهاتف** — شبكة ملفوفة بدل شريط تمرير لمس فقط.
- **صفحة الاشتراكات في الشريط السفلي** لأصحاب المهام فقط: طلب الاشتراك ومعرفة تفاصيله من مكان واحد، مع لافتة واضحة إن عطّلت الإدارة الاشتراك.
- **بطاقة أنيقة للتثبيت والإشعارات**: زر تثبيت التطبيق بضغطة واحدة مع **شرحات خاصة بكل منصة** (أندرويد / آيفون / سطح المكتب)، وشارة "التطبيق مثبت ✓" لحظة التثبيت، وشارة "الإشعارات مفعلة ✓" لحظة السماح، وتوجيه واضح عند حظر الإشعارات.
- **تحفيز بالمستويات**: 🥉 برونزي (1+) · 🥈 فضي (5+) · 🥇 ذهبي (15+) · 💎 ماسي (30+) — تظهر بجانب اسم المنفذ/الصاحب في البطاقات، مع شريط تقدم للمستوى التالي في الملف الشخصي.
- ترجمة كاملة (ar/fr/en) لكل الميزات الجديدة + تجاوب كامل على الهاتف.

## الميزات (v4.4) — إصلاحات تجربة المستخدم والإشعارات بلغة القارئ

- **الصورة الشخصية تُحفظ وتظهر فوراً**: العطل كان أن رابط الصورة ثابت فكان المتصفح يعيد القديمة من الكاش — أُضيفت نسخة `updatedAt` للرابط (cache-busting) وتم تمديد كاش الخادم بأمان؛ الاختبار يثبت أن بايتات الصورة تتغير فعلياً بعد كل تحديث.
- **كل الإشعارات بلغة القارئ فقط**: أُزيلت النصوص المدمجة من الخادم — رسائل الإدارة (`system`)، إشعارات التعطيل/التمديد/المنح، والبث تُخزَّن بعناوين ونصوص عربية/فرنسية/إنجليزية منفصلة، والواجهة تعرض لغة المستخدم المختارة دائماً وتبدّل لغة الإشعارات القديمة عند تغيير اللغة.
- **إشعارات الدفع في الخلفية بلغة المستخدم أيضاً**: Service Worker يسأل الصفحة المفتوحة عن لغتك عبر postMessage ويعرض عنوان الإشعار بنسختها — حتى `id_pending` صار له عنوان خاص.
- **البث للجميع ثلاثي اللغة**: تبويب الإرسال في حساب الإدارة صار فيه تبويبات (العربية/Français/English) لعنوان ونص كل لغة مع علامة ✓ لكل لغة مكتملة، ولا يُرسل إلا مكتملاً — كل مستخدم يقرأ الإعلان بلغته.
- **النص الحر للإدارة (سبب رفض التوثيق، قرار الشكوى) يظهر في سطر خاص** بدل خلطه داخل الجملة المترجمة.
- **بطاقة المستوى بلا تناقض**: مع 0 مهام تظهر «أكمل أول مهمة لترتقي» مع شريط تقدم نحو برونزي — ولا يظهر «وصلت لأعلى مستوى» إلا عند 💎 فعلاً.
- **بطاقة «ثبّت التطبيق وفعّل الإشعارات» مرة واحدة** في صفحة حسابي (كانت متكررة).
- **«كيف أثبّت التطبيق؟» يشمل المنصات الثلاث**: الحاسوب (Chrome/Edge) وأندرويد وآيفون — جهازك الحالي يظهر أولاً مع علامة ✓.
- **رمز العملة**: «دج» في كل الواجهة العربية و«DA» في الفرنسية والإنجليزية — عبر مفتاح الترجمة في 8 مواضع (صفر نصوص ثابتة).
- **تصحيح العبارة**: «البحث عن المهام مجاني تماماً».
- **اختبارات**: API v4.4 (الصورة + اللغة النقية + البث): **9/9 ✓** — typecheck نظيف.

## الميزات (v4.13) — إصلاح تسجيل الدخول بواسطة Google

- **سبب خطأ `404 DNS_HOSTNAME_RESOLVED_PRIVATE`**: نشر Vercel كان يحمل rewrite خاصاً ببيئة التطوير المحلي (`/api/* → http://localhost:3100`) من عصر بيئة العمل. زر Google يذهب مباشرة إلى Railway، لكن **عودة Google من شاشة الموافقة** تهبط على `vercel.app/api/auth/google/callback` فكان الـrewrite يرسل حافة Vercel إلى localhost (عنوان خاص مرفوض) فتموت العملية بذلك الخطأ. الآن الـrewrite لا يُركّب إلا عند غياب `NEXT_PUBLIC_API_URL` (تطوير محلي حصراً) — في الإنتاج لا وجود له إطلاقاً.
- **الإعدادات الصحيحة للتدفق** (هذا الملف يشرحها و`.env.example` توثّقها): على Railway يجب `APP_URL=<رابط الواجهة>` (الـcallback يعيد المستخدم إلى `APP_URL/#social-token`) و`GOOGLE_REDIRECT_URI=<رابط Railway>/api/auth/google/callback`، وفي Google Console تُسجَّل نفس قيمة Railway في «Authorized redirect URIs». متغيرات `GOOGLE_*` على Vercel غير مطلوبة (المعالجة كلها على الخادم).
- **تحذير إعدادات عند الإقلاع**: إذا رُكِّب `GOOGLE_CLIENT_ID` وبقي `APP_URL` على قيمة localhost الافتراضية يطبع الخادم تحذيراً واضحاً في سجلات Railway فور الإقلاع بدل فشل صامت عند الدخول.
- **اختبارات**: سباكة OAuth كاملة **9/9 ✓** (راية providers، رابط الموافقة بـredirect_uri/client_id/state، حراس الـcallback الثلاثة يعيدون للواجهة بـ`#social-error` الصحيح، انحدار اللغات ×9) + src صفر أخطاء + انحدار v4.4→v4.12 + sw `slekni-v4-13`.

## الميزات (v4.1) — إصلاح تشغيل الفيديو

- **السبب الجذري** (مثبت باختبارات بايت-ببايت): بث الفيديو عبر HTTP Range كان يسلّم **بايتًا واحدًا أقل** مما يعلنه `Content-Length` في كل استجابة جزئية، لأن `GridFSBucketReadStream` يتعامل مع خيار `end` كحصري بينما الكود يمرّره شاملًا — فيتعلق المشغّل انتظارًا للبايت الأخير ولا يبدأ التشغيل أبدًا على سطح المكتب والهاتف معًا، رغم نجاح الرفع نفسه.
- **إصلاح الخادم** (`mini-services/api-server/src/routes/media.routes.ts`): نطاقات صحيحة 206 (المشغّل: `bytes=0-`، iOS: `bytes=0-1`، وسط الملف، قرب النهاية)، دعم النطاق اللاحق `bytes=-N` (آخر N بايت وفق RFC 7233)، رفض خارج النطاق بـ 416 مع `Content-Range: bytes */total`، ترويسة `Content-Disposition: inline`، استجابة `HEAD` سليمة بدون جسم، تحرير مؤشر GridFS فورًا عند إجهاض المشغّل للطلب، وتجاهل النطاقات المتعددة بأمان (استجابة كاملة 200).
- **ممشغّل محصّن** في تفاصيل العرض: عند أي فشل تشغيل (مثل webm على iOS Safari) تظهر رسالة واضحة مع زر **إعادة المحاولة** (بإبط ذاكرة التخزين المؤقت) وزر **فتح الفيديو مباشرة** في تبويب جديد للتشغيل أو التنزيل.
- **رفع أذكى**: شريط تقدم ونسبة مئوية لحظية أثناء رفع الفيديو، وعند فشل الرفع **يُلغى نشر العرض** برسالة واضحة بدل نشره صامتًا بدون الفيديو.
- اختبار E2E كامل (رفع مجزأ + بث + 7 سيناريوهات نطاقات + مصادقة + فحص ffprobe): **26/26 ✓** — والملف المنزَّل مطابق للملف المرفوع بايت-ببايت (sha256).

## تسجيل الدخول الاجتماعي — الإعداد

### Google OAuth
1. من [Google Cloud Console](https://console.cloud.google.com/apis/credentials) أنشئ **OAuth 2.0 Client ID** (نوع Web application).
2. أضف إلى **Authorized redirect URIs**: `https://<your-api-domain>/api/auth/google/callback` (ومحليًا `http://localhost:3100/api/auth/google/callback`).
3. ضع في `.env` الخاص بالخادم:
   ```
   GOOGLE_CLIENT_ID=...
   GOOGLE_CLIENT_SECRET=...
   APP_URL=https://your-frontend.vercel.app   # يُعاد إليه بعد الدخول
   ```
4. أعد تشغيل الخادم — زر Google يتفعل تلقائيًا (`/api/auth/providers`).

### Magic Link عبر البريد
ضع إعدادات SMTP في `.env` الخاص بالخادم (يعمل مع Brevo / Gmail App Password / أي SMTP):

```
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=587
SMTP_USER=...
SMTP_PASS=...
MAIL_FROM="Selekni w Nselkek <no-reply@slekni.dz>"
```

> **وضع التطوير**: افتراضيًا `MAGIC_DEV_RETURN_LINK=true` يرجع الرابط في استجابة الـAPI ليظهر في الواجهة للتجربة بدون بريد حقيقي. **ع Publication غيّرها إلى `false`** بعد ضبط SMTP.

## التشغيل محليًا على ويندوز (Local development)

### المتطلبات
- [Node.js 20+](https://nodejs.org) و npm
- MongoDB: ثبّت [MongoDB Community Server](https://www.mongodb.com/try/download/community) كخدمة ويندوز (الافتراضي `mongodb://127.0.0.1:27017`)، أو استخدم Atlas المجاني.

### 1) الخادم (API)

```bat
cd mini-services\api-server
copy .env.example .env
:: عدّل .env ثم:
npm install
npm run dev:npm        :: tsx watch — يعمل على المنفذ 3100
```

عدّل في `.env` على الأقل:
- `MONGODB_URI` — عنوان قاعدتك المحلية أو Atlas.
- `JWT_SECRET` — سلسلة عشوائية طويلة.
- `SUPER_ADMIN_EMAIL` و `SUPER_ADMIN_PASSWORD` — حساب المشرف (يُنشأ تلقائيًا عند الإقلاع).
- `APP_URL=http://localhost:3000` — تُعاد إليه redirects الدخول الاجتماعي.
- مفاتيح VAPID للإشعارات: `npx web-push generate-vapid-keys` ثم ضع المفتاح العام في `.env` هنا **وفي الواجهة**.
- (اختياري) Google + SMTP كما في القسم أعلاه.

### 2) الواجهة (Frontend)

من جذر المشروع:

```bat
copy .env.example .env.local
:: ضع NEXT_PUBLIC_VAPID_PUBLIC_KEY بنفس المفتاح العام أعلاه
npm install
npm run dev            :: http://localhost:3000
```

ولجعل الواجهة تتحدث مع الخادم المحلي مباشرة (بدون بوابة)، أضف في `.env.local`:

```
NEXT_PUBLIC_API_URL=http://localhost:3100
```

### 3) النشر لاحقًا (دليل v4.10 الكامل)

#### أ) قاعدة البيانات على MongoDB Atlas (المستوى المجاني)
1. أنشئ حسابًا على [MongoDB Atlas](https://cloud.mongodb.com) ثم **Cluster مجاني (M0)**.
2. Database Access → أضف مستخدمًا (اسم + كلمة سر). Network Access → أضف `0.0.0.0/0` (السماح لـ Railway).
3. Connect → Drivers → انسخ سلسلة الاتصال `mongodb+srv://...` وأضف اسم القاعدة في نهايتها: `...mongodb.net/slekni`.
4. هذه السلسلة هي `MONGODB_URI` في الخطوة التالية. (M0 مجاني ≈ 512MB — حراس v4.10: حد فيديو 30MB + مسح GridFS اليتيم + سقف إشعارات 150 يحمونها).

#### ب) الخادم (Backend) على Railway
1. أنشئ حسابًا على [Railway](https://railway.app) → **New Project → Deploy from GitHub repo** → اختر مستودع التطبيق.
2. داخل الخدمة → **Settings → Build**: فعّل **Root Directory** واكتب `mini-services/api-server` — ملف `railway.json` الموجود هناك يضبط كل شيء تلقائيًا (NIXPACKS + `bun install` + `bun src/index.ts` + فحص صحة على `/api/settings`).
3. **Variables** → ألصق المتغيرات من `mini-services/api-server/.env.example` (الإلزامي: `MONGODB_URI` و`JWT_SECRET` — والأفضل ضبط `APP_URL` برابط Vercel و`ALLOWED_ORIGINS`).
4. **Settings → Networking → Generate Domain** — انسخ الرابط الناتج مثل `https://slekni-api-production.up.railway.app` — **هذا هو رابط السيرفر الذي تبحث عنه**.

#### ج) ربط الواجهة بالخادم — ★ أين ألصق الرابط؟ ★
- **محليًا**: افتح الملف **`.env.example` في جذر المشروع** — ستجد الموضع مُبرَزًا بعلامات ★★★:
  ```
  NEXT_PUBLIC_API_URL=https://slekni-api-production.up.railway.app
  ```
  انسخ الملف إلى `.env.local` والصق الرابط بعد `=`.
- **على Vercel**: Project → **Settings → Environment Variables** → أضف:
  - `NEXT_PUBLIC_API_URL` = رابط Railway من الخطوة (ب)
  - `NEXT_PUBLIC_VAPID_PUBLIC_KEY` = نفس مفتاح VAPID العام لدى الخادم
  ثم **Deployments → Redeploy** (متغيرات `NEXT_PUBLIC_*` تُثبَّت وقت البناء ولا تسري إلا بعد إعادة نشر).
- بعد ذلك كل نداءات البيانات والصور والفيديو تذهب **مباشرة من متصفح المستخدم إلى Railway** — لا تمر عبر Vercel إطلاقًا (هذه هي حماية Fast Origin Transfer).

#### د) حماية باقة Vercel المجانية (Fast Origin Transfer 10GB)
- لا بيانات عبر Vercel: كل الـ API يُقدَّم من Railway (`NEXT_PUBLIC_API_URL`)، وVercel يقدّم الهيكل الثابت فقط (كاش `immutable` من `vercel.json` + Service Worker).
- الصور مضغوطة في المتصفح قبل الرفع (500KB كحد لكل صورة)، والفيديو ≤ 30MB يُبثّ من GridFS بدعم Range، و`sw.js` بـ`no-cache` حتى تصلك التحديثات فورًا.
